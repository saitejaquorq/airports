<!-- sdlc:auto:start overview -->
This repository is a two-part airport directory app generated by the Quorq AI SDLC platform: a React 19 + Vite single-page frontend with approved, reviewed screens that currently render seeded sample data, and a FastAPI backend that exposes unauthenticated read-only endpoints for searching and looking up airports. The backend persists airport records in a SQL database (SQLite by default, Postgres in the approved architecture) managed through Alembic migrations, loads the bundled OurAirports CSV on first startup, and mirrors that data into a Meilisearch index to power search. The frontend and backend are not yet wired together in code; `src/lib/api.ts` is the prepared integration seam for that work.
<!-- sdlc:auto:end overview -->

- Docker and Docker Compose (optional, for Postgres and Meilisearch via docker-compose.yml)

<!-- sdlc:auto:start setup -->
1. Clone the repository.
2. Backend: cd backend && pip install -r requirements.txt
3. (Optional) Start Postgres and Meilisearch for the full architecture: from the repo root run `docker compose up -d`
4. Apply database migrations: cd backend && alembic upgrade head
5. Set DATABASE_URL (e.g. to point at the Postgres container) if not using the SQLite default; see backend/app/database.py
6. Start the backend: cd backend && uvicorn app.main:app --reload (loads the bundled CSV and builds the search index on first run if the airports table is empty)
7. Frontend: cd frontend && npm install
8. Start the frontend: npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component under app/routers/, registered in app/main.py
- One Pydantic schema pair per entity in app/schemas.py, mirroring the SQLAlchemy models in app/models.py
- Schema changes happen only via Alembic migrations in backend/alembic/versions/, not via runtime table creation
- The airports table is treated as read-only at the application layer; only app/importer.py writes rows
- Backend tests are separated into tests/unit, tests/integration, and tests/acceptance
- DATABASE_URL and ALLOWED_ORIGINS are read from environment variables with local-friendly defaults (SQLite, localhost:5173)
- Frontend screens live one-per-file under src/screens/, routed from src/App.tsx
- Shared UI/icon vocabulary and brand tokens live in src/lib/ui.tsx, src/lib/icons.tsx, src/lib/brand.ts, and index.css
- Frontend screens currently render seeded sample data; src/lib/api.ts is the prepared seam for wiring real API calls
- Linting/formatting: ESLint + Prettier on the frontend, Ruff (check and format) on the backend
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the API fail with a CORS error in the browser console | Set ALLOWED_ORIGINS on the backend to include the frontend's origin, or rely on the built-in localhost:5173 dev defaults in app/main.py |
| GET /airports/search returns 503 Service Unavailable | Meilisearch is not reachable; start it (e.g. via `docker compose up -d`) and ensure the backend's Meilisearch configuration points at it |
| `pytest` run from the repo root fails with ModuleNotFoundError: No module named 'app' | Run pytest from the backend/ directory, where pytest.ini sets pythonpath = . |
| `npm run build` succeeds but the app breaks a stricter deploy/typecheck step | `npm run build` does not typecheck; run `npm run typecheck` (tsc --noEmit) separately before shipping |
| Backend starts but the airports table stays empty / search returns no results | Ensure Alembic migrations have been applied (`alembic upgrade head`) before startup; the importer only populates an existing, empty airports table from backend/data/airports.csv |
<!-- sdlc:auto:end troubleshooting -->
